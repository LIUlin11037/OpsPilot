# 使用 PostgREST 进行 v1.0 独立接入验收

PostgREST 是本次预留的新目标。隔离环境使用 PostgREST v13.0.8 和 PostgreSQL 16.11，并把一个合成数据表交给仅有 SELECT 权限的角色。OpsPilot 读取两个回环 HTTP 端点，无需数据库凭据。PostgREST 的 `/ready` 检查连接池和 schema cache，`/live` 检查服务进程。[PostgREST 健康检查文档](https://docs.postgrest.org/en/v13/references/admin_server.html)

## 环境准备

在仓库根目录启动单独的 Compose 项目。

```powershell
docker compose -p opspilot-v1-postgrest -f examples/postgrest-health/compose.yaml up -d
curl.exe --max-time 5 -sS -o NUL -w "%{http_code}\n" http://127.0.0.1:18752/ready
```

当 `/ready` 和 `/live` 均返回 200，且候选包安装完成，即可开始。Docker 和安装准备时间另计。[候选包安装](v1.0-release-candidate.md#构建和安装)

2026 年 11 月 24 日用原始 HTTP GET 核对了隔离环境。启动后 `/ready` 和 `/live` 均返回 200。停掉本示例中的 PostgreSQL 后分别返回 503 和 200，恢复后均返回 200。也核对了数据库读取角色有 SELECT 权限，没有 INSERT、UPDATE 或 DELETE 权限。首次使用者需要另行完成 OpsPilot 接入并记录耗时。

本轮 PostgREST 镜像摘要为 `sha256:d09618df2b7b9547c80a076c2f4045b326be8d7ac06060d263caefec1334e3c9`，PostgreSQL 镜像摘要为 `sha256:4327b9fd295502f326f44153a1045a7170ddbfffed1c3829798328556cfd09e2`。

## 首次使用者的任务

1. 将指南中的 `$python` 指向已安装候选包的 Python。按候选包文档安装时为 `.\.opspilot\v1-candidate\install-env\Scripts\python.exe`。开始计时，照首次接入指南复制最小配置。在 `health.service_url` 填入 `http://127.0.0.1:18752/ready`，在 `health.dependency_urls` 数组中添加 `http://127.0.0.1:18752/live`，作为同一服务的存活对照。使用专用本地工作目录，例如 `.opspilot/v1-independent-http`。[首次接入指南](first-http-target.md)
2. 预览、诊断并按任务 ID 回读首份 Markdown 报告。停止计时，记录实际用时、修改过的文件和卡点，首份报告目标为 30 分钟内。报告应以 200 记录主端点，默认依赖可标记为条件未满足。
3. 按下面的命令停止隔离数据库。当 `/ready` 返回 503 时，按指南生成故障报告。同时核对本次报告中的 `/live` 观测。

   ```powershell
   docker compose -p opspilot-v1-postgrest -f examples/postgrest-health/compose.yaml stop db
   ```

4. 重新启动隔离数据库。等待 `/ready` 返回 200，再用同一份配置运行复查。比较健康到故障及故障到恢复两组报告，记录三份报告的任务 ID 和实际变化。

   ```powershell
   docker compose -p opspilot-v1-postgrest -f examples/postgrest-health/compose.yaml start db
   ```

比较的依据是 `/ready` 反映就绪状态、`/live` 反映服务能否响应。知道停掉了数据库来自隔离环境的操作记录。查询报告中的根因仍按应用实际观测判断。

交回首份报告的用时、三个任务 ID、两组状态变化、实际改动清单和卡点。使用已有日志或业务检查点补充归因时，另外记录接入了哪些来源以及为此修改了哪些文件。
