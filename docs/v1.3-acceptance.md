## 执行中的问题与复核

- 接入者在独立目录生成三份目标配置，依次接入 HTTP、Prometheus 和访问日志。验收环境预先用 Prometheus 的指标重标记将 Traefik 的 `code` 复制到 `status`，用轻量脚本将其访问日志转换为已有 JSONL 契约。OpsPilot 接入期间只修改独立目录的配置和产物。
- 默认沙箱拒绝 Docker API。使用限定范围的权限操作专用 Compose 项目并读取它的日志。原始数据复核中，执行者在独立脚本内处理了 Python 3.10 的纳秒时间戳解析。故障命令在退出时恢复后端，独立验收结束后清理了本轮隔离容器。
- 首轮发现 Markdown 计划表把同一来源的两条查询显示为配置调用数 1。计划和保存的 JSON 均为 2，实际调用数也为 2。修正后构建并在新虚拟环境离线安装 `1.3.0rc2`，wheel 的 SHA-256 为 `4486bd7139843031e4ecbf058e0d073859e73dfc4f37eb072358bb0b9cabe0be`。用该版本重读五份 SQLite 报告，四张相关 Markdown 表显示 2 次配置、2 次记录，所有 JSON 和数据库摘要一致。

三个配置、五份原始报告、SQLite、计时、原始指标、访问日志和独立核对记录均存于本地 `.opspilot/v13-first-user/`。修正后回读的 Markdown 位于 `.opspilot/v13-rc2/reread/`。
