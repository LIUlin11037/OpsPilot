候选包版本为 `1.0.0rc1`。验收使用规则路径，模型辅助仍可按既有评测门槛单独启用。外部发布以通过验收的提交为依据。

## 构建和安装

在仓库根目录用 Python 3.10 或更高版本执行。下列 PowerShell 命令生成 wheel 和所需的运行依赖，随后在独立环境中从 wheel 目录安装。构建阶段可访问依赖源，安装阶段只读本地 wheel 目录。

```powershell
$work = ".opspilot/v1-candidate"
$wheelhouse = Join-Path $work "wheelhouse"
$envPath = Join-Path $work "install-env"
python -m pip wheel --wheel-dir $wheelhouse .
python -m venv $envPath
$candidate = Join-Path $envPath "Scripts/python.exe"
& $candidate -m pip install --no-index --find-links $wheelhouse "opspilot==1.0.0rc1"
& $candidate -m pip check
& $candidate -m opspilot
& (Join-Path $envPath "Scripts/opspilot.exe") --help
& $candidate -m opspilot evaluate-routing --rules-only
```

用已安装的候选包执行至少一次隔离诊断并按任务 ID 回读。安装验收要核对发行元数据版本和模块实际加载路径，确认从候选环境的 `site-packages` 导入。

## 验收前约定

| 场景 | 应保存的证据 | 结论边界 |
| --- | --- | --- |
| 主服务健康 | 主端点成功，条件未触发的依赖标记为跳过。 | 能确认主端点正常。依赖需要显式复查才有本轮健康观测。 |
| HTTP 依赖故障 | 服务端点异常、已配置依赖的观测，保留各自来源与时间。 | 可指出本轮异常端点和读取缺口。根因依赖额外证据。 |
| RabbitMQ 积压 | 区分待投递、待确认、消费者数量及端点健康。 | 队列统计可描述积压。单条处理结果需要精确消息 ID 的业务记录。 |
| 单条记录缺失 | 仅在指定 ID 的查询成功并返回零条时记录缺失。 | 查到的其他 ID 不能作为目标证据。 |
| 权限不足 | 失败来源、权限原因，以及此前已取得的独立证据。 | 无法读取的业务状态为未知。 |
| 超时或观测信号不同 | 来源、调用结果、决策引用和停止原因。 | 保留彼此独立的观测，根因仍由证据约束。 |
| 恢复与复查 | 前后报告、各自的观察时间，以及条件跳过记录。 | 显式复查结果与默认跳过分开。 |
| 进程中断 | 原任务 ID、已保存步骤、中断尝试、新一轮复查的任务 ID。 | 已落盘证据沿用。未落盘的只读步骤按约定有限补读。 |
| 旧报告 | 从旧版实际生成的 SQLite 回读 JSON 和 Markdown。 | 原任务 ID、问题、状态与观测字段应保留。 |

真实环境回归须分别记录测试版本、隔离条件、输入和结果。第三方首次接入结果单独计时，从环境和只读入口就绪到回读首份报告，以 30 分钟内为目标。[完整验收条件](implementation-roadmap.md#v10-的最终验收)
