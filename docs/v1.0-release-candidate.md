# OpsPilot v1.0 发布候选验收

候选包版本为 `1.0.0rc1`。验收使用规则路径，模型辅助仍可按既有评测门槛单独启用。外部发布以通过验收的提交为依据。

## 构建和安装

在仓库根目录用 Python 3.10 或更高版本执行。下列 PowerShell 命令生成 wheel 和所需的运行依赖，随后在独立环境中从 wheel 目录安装。构建阶段可访问依赖源，安装阶段只读本地 wheel 目录。

```powershell
$work = ".opspilot/v1-candidate"
$wheelhouse = Join-Path $work "wheelhouse"
$envPath = Join-Path $work "install-env"
python -m pip wheel --wheel-dir $wheelhouse .
python -m venv $envPath
$candidate = Join-Path $envPath "Scripts/python.exe"
& $candidate -m pip install --no-index --find-links $wheelhouse "opspilot==1.0.0rc1"
& $candidate -m pip check
& $candidate -m opspilot
& (Join-Path $envPath "Scripts/opspilot.exe") --help
& $candidate -m opspilot evaluate-routing --rules-only
```

用已安装的候选包执行至少一次隔离诊断并按任务 ID 回读。安装验收要核对发行元数据版本和模块实际加载路径，确认从候选环境的 `site-packages` 导入。

## 验收前约定

| 场景 | 应保存的证据 | 结论边界 |
| --- | --- | --- |
| 主服务健康 | 主端点成功，条件未触发的依赖标记为跳过。 | 能确认主端点正常。依赖需要显式复查才有本轮健康观测。 |
| HTTP 依赖故障 | 服务端点异常、已配置依赖的观测，保留各自来源与时间。 | 可指出本轮异常端点和读取缺口。根因依赖额外证据。 |
| RabbitMQ 积压 | 区分待投递、待确认、消费者数量及端点健康。 | 队列统计可描述积压。单条处理结果需要精确消息 ID 的业务记录。 |
| 单条记录缺失 | 仅在指定 ID 的查询成功并返回零条时记录缺失。 | 查到的其他 ID 不能作为目标证据。 |
| 权限不足 | 失败来源、权限原因，以及此前已取得的独立证据。 | 无法读取的业务状态为未知。 |
| 超时或观测信号不同 | 来源、调用结果、决策引用和停止原因。 | 保留彼此独立的观测，根因仍由证据约束。 |
| 恢复与复查 | 前后报告、各自的观察时间，以及条件跳过记录。 | 显式复查结果与默认跳过分开。 |
| 进程中断 | 原任务 ID、已保存步骤、中断尝试、新一轮复查的任务 ID。 | 已落盘证据沿用。未落盘的只读步骤按约定有限补读。 |
| 旧报告 | 从旧版实际生成的 SQLite 回读 JSON 和 Markdown。 | 原任务 ID、问题、状态与观测字段应保留。 |

真实环境回归须分别记录测试版本、隔离条件、输入和结果。第三方首次接入结果单独计时，从环境和只读入口就绪到回读首份报告，以 30 分钟内为目标。[完整验收条件](implementation-roadmap.md#v10-的最终验收) · [支持与兼容范围](v1.0-compatibility.md)

## 独立接入验收

2026 年 11 月 26 日，经用户确认沿用 v0.2 的验收方式。未参与开发和指南编写的 Codex 在全新上下文中使用已安装的 `1.0.0rc1`，按仓库指南对首次接入的 PostgREST v13.0.8 和 PostgreSQL 16.11 隔离实例执行验收。验收任务在环境就绪后于北京时间 10:00:23 开始，10:01:13 回读首份 Markdown 报告，用时约 **51 秒**，达到 30 分钟目标。用时包含查阅指南、配置、预览、诊断和回读。[独立接入环境与操作](v1.0-independent-onboarding.md)

| 阶段 | 任务 ID | `/ready` | `/live` | 诊断状态 |
| --- | --- | --- | --- | --- |
| 健康基准 | `6deeb50d-734a-43a8-b8c9-1e6248a57a1f` | 200 | 按条件跳过 | `no_failure_observed` |
| 停止隔离数据库 | `8b10e36d-a880-4fc2-977e-b208d3d7a3b3` | 503 | 200 | `undetermined` |
| 恢复并显式复查 | `22603153-d0cd-45d2-bc85-00df05e39a12` | 200 | 200 | `no_failure_observed` |

`compare-http` 的健康到故障对比记录 `/ready` 从 200 到 503、`/live` 从条件跳过到 200。故障到恢复对比记录 `/ready` 从 503 到 200，前后报告中的 `/live` 均为 200。数据库停机来自隔离演练记录。应用证据表明就绪端点异常时进程仍能响应，具体故障依赖仍需独立来源确认。验收结束时原始 GET 再次确认两个端点均为 200。

复核使用同一候选包，从独立验收的 SQLite 重新读取三个任务的 JSON 和 Markdown，并重新生成两组对比，均与留存输出一致。回读和对比前后的 SQLite 摘要一致。

接入仅需在本地样例副本 `target.json` 配置主端点和存活端点。两者通过回环地址提供只读 GET，无需数据库凭据。验收未增加目标适配器。首份报告无接入阻塞。故障演练的默认沙箱拒绝 Docker 连接，随后通过限定范围的授权，仅启停专用 Compose 项目的数据库。配置、预览、SQLite、三份报告、两组对比及计时记录保存在本地 `.opspilot/v1-independent-http/`。
