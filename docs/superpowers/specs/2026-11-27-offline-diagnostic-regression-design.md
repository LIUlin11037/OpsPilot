# OpsPilot v1.5 离线诊断回归设计

## 目标

维护者在断网、无模型密钥的环境里用一条命令重跑代表性诊断。每个案例都有预先写好的期望，逐项核对诊断状态、证据引用、观察范围和缺口。任何不匹配都会指出案例及字段，并使命令以非零状态退出。

## 方案

| 方案 | 覆盖范围 |
| --- | --- |
| 完整诊断入口，已选 | 在本机回环地址返回固定 HTTP 响应，通过现有 `diagnose-auto` 读取目标配置、收集证据并写入 SQLite，再用 `report` 回读。也覆盖连接器解析、日志筛选和报告保存。 |
| 诊断逻辑回放 | 从现有只读工具契约直接提供结果。执行较轻，适合定位 Core 分支，配置、连接器和存储需另外验证。 |

回归由仓库内的独立入口执行。每次在临时目录生成目标配置、日志和数据库。服务地址只使用本机回环，外部连接在离线验收中拦截。使用规则路径，沿用现有诊断 CLI、连接器和报告查询。回归过程中不启动 Docker 或访问 HireHub。

## 案例与依据

从 Traefik 的隔离 HTTP 统计、Prometheus 范围查询和访问日志中提取最小观测，保留来源和提取规则。可提交数据仅保留状态、指标值、相对时间和替换后的服务标识。实时滚动指标根据请求窗口重建采样时间，历史窗口使用固定边界。模拟的异常或干扰单独标注。期望在写执行入口前固定，根据原始观测、配置范围和业务标识约定形成。[Traefik 验收](../../v1.3-acceptance.md)

| 案例 | 必须看见的结果 |
| --- | --- |
| 健康基准 | 已配置健康探针返回 200，观测状态为健康，整体状态为 `no_failure_observed`。 |
| HTTP 故障 | HTTP 504 与目标服务的错误率、延迟异常均有观测支持，原因仍为 `undetermined`。 |
| 恢复后的历史异常 | 当前探针为 200。历史窗口仍有日志和指标异常，引用对应证据索引。 |
| 历史指标来源超时 | 保留成功的当前探针和历史日志。标记超时来源、窗口状态及缺失证据索引，整体状态为 `undetermined`。 |
| 相邻服务与时段干扰 | 目标窗口内无异常时，把相邻服务的错误和窗口外的目标错误排除在结论之外。 |
| 无关消息 ID | 查询成功且返回零条匹配记录。别的消息失败记录不得归到所查消息，队列积压原因仍为 `undetermined`。 |

## 验证与交付

- 回归入口输出逐案结果。差异带案例 ID、字段路径、期望值和实际值。只比较稳定语义，对时间范围和证据索引做明确断言。时间点的绝对值、每次启动的任务 ID 和实际耗时不作为固定预期。
- 在独立目录关闭模型配置并禁止外部网络，执行文档命令并保存基线。用测试专用的预期副本制造一个不匹配，核对诊断命令成功且回归命令返回非零。
- 依次提交案例数据与预期、回归入口与验证、实际诊断修复及验收记录。每笔提交前运行 `python -m opspilot` 和 `python -m pytest`。推送、打标签和发布另行授权。
