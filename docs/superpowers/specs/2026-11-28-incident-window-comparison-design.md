# OpsPilot v1.8 故障窗口对比与恢复复查

给出两个已保存的历史调查任务 ID，就能查看当前 HTTP 探针和历史观测分别发生了什么变化。两个输入按用户给出的顺序显示。读取仅使用现有 SQLite，导入离线交接包后也能使用。

```powershell
python -m opspilot compare-incident BEFORE_ID AFTER_ID
python -m opspilot compare-incident BEFORE_ID AFTER_ID --format markdown
```

## 入口选择

| 方案 | 取舍 |
| --- | --- |
| 独立的 `compare-incident`，已选 | 两份输入必须是历史调查报告。结果能直接围绕窗口、证据和缺口组织。 |
| `compare-http --include-incident` | 可沿用原命令，但需要为普通 HTTP 报告和历史报告的混合输入定义更多行为。 |

## 范围与证据

- 两份报告都须存在，且服务标识与 HTTP 探针 URL 须一致。无法读取或报告类型不符时指出具体任务。按带时区的实际时刻比较窗口，区分同一窗口、重叠、第二个窗口在前、第二个窗口在后。窗口端点重合算重叠。保留 `compare-http` 的现有接口。
- 每份报告分别列出任务 ID、当前 HTTP 结果和观测时间、历史起止时间和历史结论。每条证据索引引用自己的任务。比如当前 HTTP 从 503 变为 200 时，两份报告仍可以引用同一历史异常。
- 历史日志只比较相同来源和服务范围的可用证据。原始错误计数的直接对比要求窗口等长，时长不同则分别保留原始值并说明限制。历史指标按查询名对应，核对来源、服务、表达式、单位、采样步长和阈值。若某项缺失、取证失败、范围不完整或配置不同，列出对应原因，保留其他可用证据。后续窗口结论用已观察到的异常及缺口表达，现有报告状态作为该报告自己的观测结果。
- v1.7 请求追踪按任务展示候选、覆盖状态、跨度证据索引、跳过原因和缺口。某份未启用追踪时明确标记。请求追踪始终按原任务及 Trace ID 阅读，查询列表变化只说明两份报告取证范围不同。比较过程只读旧报告，不会重新请求目标、使用模型或写入诊断任务。

## 验收

- 离线用例覆盖不同服务、错误报告类型、时区等价、窗口重叠或倒序，以及同源指标、配置变化、来源缺失和 v1.7 追踪。保存报告后对照 JSON 与 Markdown 的证据引用，并复验原有 `compare-http`。
- 复用现有隔离 HTTP 与 Prometheus 样例，生成故障时、当前探针恢复后复查同一窗口、后续窗口和其中一项来源缺失的报告。对比脚本在观测服务停止后仍能运行。保留任务 ID、结果、复现步骤和覆盖边界。
- 按对比契约、CLI 与报告、验收材料拆分小提交。每笔提交前运行 `python -m opspilot` 和 `python -m pytest`，复验 v1.5 与 v1.7。推送另行授权。
