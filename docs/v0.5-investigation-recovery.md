# OpsPilot v0.5 调查恢复与复查

执行 `diagnose-auto --workflow investigation` 时，OpsPilot 先把任务 ID、来源、检查条件和预算存入报告使用的 SQLite，然后在终端显示 ID，再开始读第一个来源。计划预览仍只解析配置。恢复从数据库读取保存的计划，RabbitMQ 凭据继续从当前环境读取。

## 查看与继续任务

使用相同的 `--db` 路径，并将 `TASK_ID` 替换为执行时显示的 ID。

```powershell
$python = ".\.venv\Scripts\python.exe"
$db = ".opspilot/reports.sqlite3"
$taskId = "TASK_ID"
& $python -m opspilot --db $db task $taskId
& $python -m opspilot --db $db resume $taskId
& $python -m opspilot --db $db report $taskId --format markdown
```

| 观察项 | 含义 |
| --- | --- |
| `status = unfinished` | 任务还未写入最终报告。已落盘证据可在 `checkpoint.evidence` 中查看。 |
| `status = completed` | 最终报告和完成状态在同一个事务中写入。重复执行 `resume` 返回同一份报告。 |
| 尝试为 `started` | 已持久化开始记录，结果尚未落盘。若进程中断，下一次获得任务锁的执行者将它标记为 `interrupted`。 |
| 正在有另一进程执行 | 重叠的恢复请求以退出码 1 提示该任务已有执行者。它不会读取来源或写入步骤。 |

恢复跳过已落盘的步骤。单个步骤若在保存结果前中断，可以再读一次。两次尝试均中断时，记录 `interruption_retry_exhausted`，再按原有流程和预算判断是否继续。正常返回的成功、超时或缺失结果作为该步观察保存。每次开始的尝试在 `attempts` 中可查，包括来源、开始时间和记录到的结果。中断尝试的结束时间表示恢复时确认中断的时间。

恢复沿用原步骤预算与已记录的执行耗时。进程暂停和中断前尚未保存的时间不计入已记录用时。执行锁由本机 SQLite 管理，锁文件位于报告库旁的 `.locks` 后缀目录，持有者退出后即可重新竞争。

## 新一轮复查

```powershell
$fresh = & $python -m opspilot --db $db recheck $taskId | ConvertFrom-Json
& $python -m opspilot --db $db report $fresh.task_id --format markdown
```

恢复后的报告可能包含中断前后的证据。每项的 `observed_at` 是实际观察时间。需要更新较早的观测时，对已完成的任务执行 `recheck`。它从第一步重新采集，取得新任务 ID，用 `previous_task_id` 链接原任务。原报告及其观察时间继续可按原 ID 查阅。已有版本保存的报告也仍可用 `report` 回读。
