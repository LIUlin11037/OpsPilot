# 离线诊断交接

发送方按任务 ID 选择已保存的诊断报告。接手人拿到一个 ZIP，可以解压阅读 Markdown，也可以在本地导入后用 OpsPilot 查证据、做对比。

## 导出交接包

发送方先安装项目。在下面的命令中，将数据库路径替换为诊断时使用的文件，将任务 ID 依次替换为要交接的报告。

```powershell
python -m opspilot --db .opspilot/reports.sqlite3 reports --limit 10
python -m opspilot --db .opspilot/reports.sqlite3 export-reports --output incident.zip FAULT_TASK_ID RECOVERY_TASK_ID
```

`manifest.json` 列出选中的任务 ID 和每个文件的 SHA-256 摘要。`reports/1.md` 是第一份可直接阅读的报告，`reports/1.json` 保留同一报告的结构化证据。编号按报告在来源库中的保存顺序分配。每包支持 1 至 100 份报告，总解压大小上限为 32 MiB。

报告包含来源地址、观察时间、任务关联和已记录的观测内容。发送前可先解压检查这些内容是否适合交给接手人。

## 离线回看和比较

接手人只需要 ZIP 和已安装的 OpsPilot。以下命令在本地创建 `review.sqlite3`，同样支持导入已有的 OpsPilot 报告库。

```powershell
python -m opspilot --db review.sqlite3 import-reports incident.zip
python -m opspilot --db review.sqlite3 reports
python -m opspilot --db review.sqlite3 report FAULT_TASK_ID --format markdown
python -m opspilot --db review.sqlite3 compare-http FAULT_TASK_ID RECOVERY_TASK_ID --format markdown
```

`compare-http` 的第一个 ID 是对比起点。队列、HireHub 和 Voting App 报告也可使用各自已有的 `compare-*` 命令。导入保留任务 ID，损坏包或任务 ID 冲突会让整批导入失败。若希望单独查阅一批已有任务，可选择一个新的 `--db` 路径。
