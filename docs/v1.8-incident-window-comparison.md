# v1.8 故障窗口对比与恢复复查

`compare-incident` 接收两个已保存的历史调查任务 ID。命令从当前 SQLite 读取报告，输出 JSON 或 Markdown。两个任务须对应相同的服务和 HTTP 探针 URL。导入离线交接包后也能执行对比。

```powershell
python -m opspilot --db reports.sqlite3 compare-incident BEFORE_ID AFTER_ID
python -m opspilot --db reports.sqlite3 compare-incident BEFORE_ID AFTER_ID --format markdown
```

结果分开列出当前 HTTP 探针、历史时段与各自的异常或缺口。当前 HTTP 从 503 变成 200 后，可以复查同一历史窗口并看到原异常。用不同窗口复查时，结果会标出先后或重叠关系。每个证据索引都对应所在列的任务 ID。

同源同范围日志的原始错误数可以在等长窗口间对比。指标要求来源、服务、表达式、单位、步长和阈值一致。配置不同或来源缺失时，比较结果保留已读值和限制原因。请求追踪按任务列出 Trace ID、查到的跨度和缺口。两段窗口可以采到不同的请求。

## 复现验收

复用本机隔离的 orders HTTP 服务和 Prometheus。采集阶段运行约三分钟，通过真实 HTTP 流量产生故障和恢复观测。脚本核对原始日志、Prometheus 响应及 SQLite 回读，然后用三个对照验证 `compare-incident`。

```powershell
docker compose -p opspilot-v18-window -f examples/prometheus-health/compose.yaml up -d --wait
python examples/prometheus-health/incident_comparison_acceptance.py capture .opspilot/v18-window-example
docker compose -p opspilot-v18-window -f examples/prometheus-health/compose.yaml down --volumes
python examples/prometheus-health/incident_comparison_acceptance.py compare .opspilot/v18-window-example
```

每次指定新的输出目录。`capture` 保存 `tasks.json`、SQLite、报告与原始指标响应。`compare` 在停止容器后运行，保存三组 JSON、Markdown 及 `verification.json`，并核对 SQLite 的内容没有变化。
