# OpsPilot v1.0 之后的实施计划

2026 年 11 月 26 日制定。v1.0 的 PostgREST 验收中，就绪端点返回 503 时，进程存活端点仍返回 200。单次探针记录了当时的状态，值班人员还需要知道同一服务在故障期间的请求错误率、延迟是否升高，以及恢复持续了多久。[v1.0 验收基线](v1.0-release-candidate.md)

**下一轮的目标**是让工程师提交一次诊断后，能看到一次端点观测对应哪段服务指标、异常是否持续、还缺哪项证据，并能按任务 ID 对比恢复前后。以下版本号和门槛是规划值。v1.1 优先实现此前提议的 Prometheus 只读接入，后两阶段依据实际接入结果调整。

## 阶段与验收

| Goal | 用户得到的能力 | 完成条件 |
| --- | --- | --- |
| v1.1 Prometheus 只读指标诊断 | 通过目标配置指定服务及其错误率和延迟查询。HTTP 异常时按配置取证，也能在恢复时显式复查。 | 在真实隔离 Prometheus 上跑通健康、故障、恢复三轮，保存三份报告和两组对比。离线用例覆盖无数据、权限拒绝、超时、样本过期和查询超限。旧 HTTP 配置和 v1.0 报告仍可使用。 |
| v1.2 按故障时段调查 | 即使当前探针已恢复，也能针对过去的异常时段，关联 v1.1 的指标和已有的服务日志，看到每个判断引用的证据。 | 在同一轻量目标上分别复现故障持续、故障已结束但窗口内留有证据两种情形。加入相邻服务的错误和一个缺失来源，核对服务、时间窗、证据引用与停止原因。对单条请求的判断仍须有匹配的业务标识。 |
| v1.3 跨项目独立验收 | 首次使用者可为另一个已有指标入口的项目配置相同流程，完成一次诊断交接。 | 预留未参与前两阶段开发的项目，提前写明可支持的结论。独立执行者从环境就绪到回读首份报告以 30 分钟为目标。在相同故障下对照仅 HTTP 与启用指标的报告，记录多回答了哪个问题、额外查询数和耗时。至少一例新增判断须有原始观测支持，错误业务归因须为零。 |

## v1.1 的四个可提交任务

1. **先交付可预览的配置。** 在现有目标配置中增加可选指标来源，复用 `diagnose-auto --plan` 显示目标服务、允许的查询、回看窗口和触发条件。服务标识、指标名称和单位由目标配置提供，凭据从环境读取。验收时在 Prometheus 离线的情况下运行预览，检查非法窗口能定位到字段，旧配置生成原有检查范围。
2. **交付一个可单独验证的只读连接器。** 从配置选择已命名的查询，用 Prometheus 范围查询读取错误率及延迟。限制窗口、采样步长、超时、序列数和样本数。保留查询标识、来源、单位、窗口、样本时间及数量。用固定响应验证真实零值、空结果、过期样本、权限拒绝、超时和超限各自的含义。阈值按目标配置解释。[Prometheus HTTP 查询 API](https://prometheus.io/docs/prometheus/latest/querying/api/#range-queries)
3. **把证据带回已有 CLI 和报告。** Core 根据 HTTP 观测和显式复查决定是否查询，在剩余调查预算内取证。SQLite、JSON 和 Markdown 均保留触发或跳过的理由。对比只匹配服务、查询语义和单位一致的证据，显示各自的观察窗口。验收时断开指标来源，按原 ID 回读先前成功的 HTTP 证据，并回读一份 v1.0 真实报告。
4. **用真实指标验收。** 使用能产生请求计数和延迟直方图的轻量服务及隔离 Prometheus。示例选用 HTTP 5xx 请求占比和 p95 请求延迟，预先写明单位、阈值和流量脚本。保存健康基准，制造请求错误和耗时上升，再恢复。每轮用同一查询及起止时间核对原始响应。恢复时覆盖完整的恢复采样窗口，分别记录端点恢复时间和指标回落时间。交付配置样例、复现命令、三个任务 ID、两组对比和本轮支持范围。

## 执行约定

每个任务以一项可单独验证、回退的改动为提交边界。连接器负责读取，Core 负责下一步决策，适配器负责业务含义。默认测试使用离线数据和规则路径，阶段验收使用隔离服务。提交前运行 `python -m opspilot` 和 `python -m pytest`。HireHub 仅作只读验证，推送、标签和 GitHub Release 按单独授权执行。[项目开发约定](../AGENTS.md)

v1.1 已完成真实三轮诊断、报告对比和 v1.0 兼容复验。隔离实验记录了 HTTP 端点先恢复、滚动指标随后回到阈值以内的过程，该数据可作为 v1.2 故障窗口调查的基线。[v1.1 配置和验收记录](v1.1-prometheus.md)

v1.2 已用同一隔离目标复验故障当下、端点恢复后和日志缺失三种情况。报告可分别回读当前探针、固定历史窗口、异常依据与证据缺口。[v1.2 配置和验收记录](v1.2-incident-window.md)

v1.3 已在此前未接入的 Traefik 隔离项目通过独立验收。首次回读用时约 2 分 22 秒。同一次故障中，启用指标的报告用两条额外查询确认目标路由的滚动 5xx 占比达到 100%。恢复及历史窗口也完成了复查。[v1.3 独立验收记录](v1.3-acceptance.md)
