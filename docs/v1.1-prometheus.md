# Prometheus 只读指标诊断

在现有目标配置中加入 `prometheus`，使用 `diagnose-auto` 的 HTTP 健康工作流。HTTP 异常或无法判断时，OpsPilot 读取配置中的服务指标。基准和恢复复查可加 `--check-metrics`。报告保留探针及各指标的独立观测，`compare-http` 会配对服务、查询表达式、单位、来源和采样步长一致的指标。

## 配置

从示例复制配置，填写健康探针、Prometheus HTTP(S) 基础地址和目标的 `job` 标签值。为需要查询的指标填入实际名称、单位和上限阈值。HTTP 5xx 占比使用带 `status` 标签的请求计数器，单位为 `ratio`。p95 延迟使用经典直方图的 `_bucket` 指标，单位为 `seconds`。需要 Bearer 鉴权时，由执行环境提供 `OPSPILOT_PROMETHEUS_TOKEN`。使用授权的只读查询入口。[目标配置示例](../examples/prometheus-health/target.json)

查询使用精确的 `job` 匹配和一分钟滚动速率，以 HTTP 观测时间为结束点。配置可调整 15 至 900 秒的回看窗口、至少 5 秒的采样步长及 1 至 10 秒的查询组超时。每个查询预期聚合为一条序列，样本上限由窗口和步长决定，响应体上限为 256 KiB。报告分别记录窗口末端的有效值、窗口峰值及是否超过目标阈值。最新有效样本距窗口结束超过两步时，记录为样本过期。[Prometheus 范围查询 API](https://prometheus.io/docs/prometheus/latest/querying/api/#range-queries)

```powershell
python -m opspilot diagnose-auto --config examples/prometheus-health/target.json --plan "HTTP health"
python -m opspilot diagnose-auto --config examples/prometheus-health/target.json "HTTP health"
python -m opspilot diagnose-auto --config examples/prometheus-health/target.json --check-metrics "HTTP health recheck"
python -m opspilot report TASK_ID --format markdown
python -m opspilot compare-http BASELINE_ID FOLLOWUP_ID --format markdown
```

真实零值、无有效数据和来源故障各有独立结果。窗口的采样时间来自范围查询的求值时间。错误率和延迟描述目标服务的聚合请求表现，定位特定业务请求需要与该请求关联的其他证据。

## 隔离验收

在仓库根目录运行以下命令。验收脚本依次产生正常流量、HTTP 503 和较慢的请求，再恢复正常流量。每个阶段让一分钟滚动速率和 30 秒回看窗口覆盖当前流量，按任务 ID 核对存储报告，随后向 Prometheus 发起同时间范围的查询复核值。脚本在退出时恢复示例服务。

```powershell
docker compose -p opspilot-v11-prometheus -f examples/prometheus-health/compose.yaml up -d --wait
python examples/prometheus-health/acceptance.py .opspilot/v11-prometheus-acceptance
docker compose -p opspilot-v11-prometheus -f examples/prometheus-health/compose.yaml down --volumes
```

本次配置阈值为 HTTP 5xx 占比 0.1 和 p95 延迟 0.2 秒。基准与恢复显式查询。故障轮由 HTTP 503 触发，因此可以核对同一配置下的触发、报告和恢复窗口。

另一次复查只停止隔离 Prometheus。任务 `e5e9e481-78d1-47b9-b67a-346facf353a1` 保存 HTTP 200，两项指标均记录 `transport_error`。按任务 ID 回读结果一致，随后确认 Prometheus 恢复就绪。复现时在 Compose 命令中用 `stop prometheus` 停止监听，运行带 `--check-metrics` 的复查后用 `start prometheus` 恢复。
