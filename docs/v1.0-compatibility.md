# OpsPilot v1.0 支持与兼容范围

候选包继续支持 Python 3.10 及以上。默认规则路径、计划及报告回读可以在无模型凭据时使用。组件版本以实际验收记录为准。

| 接入入口 | 观测深度和访问条件 |
| --- | --- |
| HTTP(S) | 读取主服务和已配置依赖的 HTTP 状态。URL 提供健康端点；健康检查 2xx 为正常，424 和 5xx 为异常，认证失败或无法连接时状态为未知。 |
| RabbitMQ Management | 通过有读取权限的账号查询指定 vhost 和队列的待投递、待确认及消费者数量。消费者健康需要额外 HTTP 来源，单条消息处理状态需要独立处理记录。 |
| Redis | `redis://HOST[:PORT]` 连接执行 PING，报告可达性及响应。认证或 ACL 拒绝时记录未知。这条通用健康检查使用明文 Redis 连接。 |
| MySQL 和 MariaDB | 通过 `opspilot[hirehub]` 提供的 Python 驱动运行只读 `SELECT 1`，凭据从环境读取。特定业务表的查询由目标适配器定义。 |
| PostgreSQL | 通过应用的 HTTP 就绪端点间接观察依赖状态，或者由 Voting 适配器使用预先采集的业务快照。 |
| 本地证据 | 支持 JSONL 服务日志、业务处理记录和目标快照。订单样例直接只读访问配置中的 SQLite 业务库。 |

已存在的真实验收基线包括 RabbitMQ 3.13.7、MySQL 8.0.46、NGINX/Go/MariaDB 上游提交 `503c0dcef31b07fb77b2d4c5556bfafdf86f4f1a`、Voting 上游提交 `63e9150ca17af4ed05880d4245e486481f73fcb4`、Gitea 1.25.1 与 PostgreSQL 16.11，以及 HireHub `15ee3f9` 的投递通知链路。[v0.1 真实验收基线](v0.1-release-acceptance.md) · [Gitea 接入验收](v0.2-onboarding-acceptance.md)

## 配置与报告

- `--config` 读取 UTF-8 JSON，子段为 `health`、`rabbitmq`、`hirehub`、`voting` 和 `order`。目标配置中的相对文件路径以该文件所在目录为准。多步调查使用显式配置的 `health` 和 `rabbitmq` 范围。
- `report TASK_ID` 通过 SQLite 回读 JSON，`--format markdown` 渲染同一份报告。既有报告的任务 ID、问题、诊断状态、结论和证据保留。较新报告可增加计划、路由、工具调用和复查关联字段。
- 已完成报告可按原 ID 查看。`task`、`resume` 和 `recheck` 使用 v0.5 起为多步调查生成的持久任务记录。新复查使用新 ID 和新的取证时间，原报告仍可按原 ID 回读。
- 查询成功且零条、读取失败、条件跳过和明确健康分别记录。服务返回 200 所产生的结论以实际读取项为范围。

## 候选包实测

使用干净环境安装的 `1.0.0rc1`，回读 v0.1 真实 NGINX/Go/MariaDB 验收的健康基准 `3aef4838-9792-4cf8-91b7-ed2b8f5e6508`。JSON 与当时保存的输出相同，Markdown 核对了任务 ID、问题、原来源和 HTTP 200。回读前后报告库的 SHA-256 一致。

同一候选包运行进程中断演示。原任务 `8d716f1e-cd44-4dab-9e42-6c12809c4eef` 在保存 HTTP 503 之后、队列读取期间中断。恢复沿用原 ID 和 HTTP 观察时间，并发恢复未发起重复读取。复查任务 `6ae354d5-dffd-4b84-a7ec-661ba8e1b5b6` 保留与原任务的关联，并记录了新的 HTTP 204 观测。[复现命令](v0.5-investigation-recovery.md#隔离验收)

安装后的候选包还通过本地模拟的五条多步调查路径。含相互不同的队列注册与消费者端点观测的任务为 `da231188-6e4e-40b9-b3d7-f6a999f6e954`，保留队列超时并继续读取其他来源的任务为 `361b3ef4-a21e-4c6a-a43c-c315833aadef`。所有报告可按任务 ID 回读。[多步调查演示](v0.4-investigation.md#隔离演示)

本地订单样例为同一 `ORD-0042` 生成三份报告，先记录来源不可读，再记录查询成功但零条，最后只计入该订单的一条发货记录。第二轮仅有另一个订单的记录。三份报告按原 ID 回读一致，产物位于候选包验收目录的 `orders-a445ee82/`。[订单履约演示](v0.3-order-fulfillment.md#复现)
